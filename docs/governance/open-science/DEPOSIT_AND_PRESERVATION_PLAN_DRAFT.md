# Plano de depósito e preservação — ESQUELETO (rascunho)

Rascunho para §6.g (conservação ≥10 anos), §8 (infraestruturas). **Serviços apenas como candidatos**; nada é depositado nem escolhido por inferência (`PENDING-HUMAN`, HD-05).

## 1. Princípio
- **Git público ≠ repositório de preservação.** GitHub é desenvolvimento/distribuição, não depósito científico.

## 2. Candidatos de depósito (a decidir)
| Produto | Candidato(s) (§6.a/§8.b) | Estado |
|---|---|---|
| Publicações/teses | Sapientia (RCAAP) | `PENDING-HUMAN` |
| Dados/código/protocolos | OSF · Zenodo · Figshare · POLEN · protocols.io | `PENDING-HUMAN` |
| Software (app/skill) | Zenodo (via release GitHub) com `codemeta.json` | `PENDING-HUMAN` (depende HD-03/HD-07) |
| PGD | Argos | `PENDING-HUMAN` |
| PIDs | DataCite Fabrica (DOI); ORCID/CiênciaID | `PENDING-HUMAN` (HD-04) |

## 3. Retenção
- mínimo **10 anos**, armazenamento seguro, conforme RGPD (§6.g); prazos por conjunto: `PENDING-HUMAN`.

## 4. Formatos e integridade
- formatos abertos/simples para dados brutos; `readme.txt` por conjunto; verificação por checksum (SHA-256) no depósito: `PENDING`.

## 5. Responsabilidades e retirada
- responsável pelo depósito, política de retirada e controlo de acesso: `PENDING-HUMAN`.

## 6. Parceiros/financiadores
- regras externas podem prevalecer (§3/§6.f); inventário: `PENDING-HUMAN` (HD-06). Cláusulas reservadas **não** entram em Git público.
