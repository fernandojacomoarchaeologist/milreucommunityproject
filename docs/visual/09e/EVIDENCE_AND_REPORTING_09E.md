# Evidências e relatório

O PR deve incluir ou apontar para inventários versionados, hashes de originais, licenças, baseline e medição final, matriz requisito→implementação→teste, capturas atuais desktop/mobile sem dados pessoais e logs resumidos dos testes.

Indicar claramente o que foi observado em browser local, CI, staging e produção. Não chamar Lighthouse local de evidência de utilizador real. Não chamar demonstração de homologação backend real.

Registar também assets não otimizados, direitos pendentes, fontes descartadas, regressões aceites e motivo. A homologação UI↔backend real continua como pendência humana de staging/OAuth.
